# XInput 手柄输入采集库 — 设计文档

- 日期：2026-11-27
- 项目代号：`xinput-recorder`
- 状态：待批准（设计阶段，尚未实现）

## 1. 意图与 Why

用户需要一个**学术用途**的工具，用于记录玩家在**玩任意现成游戏时**的手柄实时输入数据，供后续行为分析（反应时、按键力度、摇杆轨迹、玩家画像等）。

关键约束（已与用户确认）：

- 用户的第一反应是"基于 Gamepad API"，但浏览器 Gamepad API 只能读取当前获得焦点的标签页，无法记录桌面客户端游戏的输入。因此路线改为 **Windows XInput 系统级采集**。
- 用户已明确选择**路线 1：Python + ctypes 直调 XInput**（放弃 pygame 事件驱动与内核驱动钩子两条路）。
- 运行环境为 Windows（当前工作台即 win32）。
- 采样精度目标：默认 1000 Hz（1 ms），可配置。这是合理默认值，由设计方拍板。
- "实时按键数据"的含义（设计方拍板，已按用户确认修订）：既要**高频采集并带精确时间戳落盘**，也要提供**边录边看的实时可视化**。按键事件、力度曲线、摇杆轨迹等完整的衍生特征仍在录制后离线后处理得到；实时画面只展示状态和简化曲线。用户已选择 **Web 仪表盘**形式。

核心机制：XInput 是共享轮询 API。游戏每帧调用 `XInputGetState()`，独立进程也可同时调用它读取同一份状态。记录器**只读**（绝不调用 `XInputSetState`、不注入输入、不抢焦点），因此游戏与记录互不干扰。

**只读性已查证（项目命门）**：MSDN 文档确认 `XInputGetState()` 返回的是"指定控制器的当前状态"快照，本身无副作用；它与 `XInputGetKeystroke()` 的事件队列相互独立。因此记录器的高频轮询既不会消耗游戏的按键事件，也不会改变游戏读到的状态——多进程同时读取是 XInput 官方支持的行为。

## 2. 目标 / 非目标 / 反目标

### 目标（Goals）
1. 后台静默记录一个或多个 XInput 手柄的完整输入状态流，游戏正常进行。
2. 提供高精度时间戳（微秒级）与可配置采样率。
3. 数据格式对分析友好（pandas 可直接读取），并附带常用衍生特征。
4. 核心库零强制第三方依赖，可 `pip install` 分发。
5. 提供 CLI 与 Python API 两种用法。
6. 提供 Web 仪表盘，边录边看实时按键/摇杆/扳机状态（副屏或手机/平板局域网访问）。

### 非目标（Non-goals）
- 不支持非 Windows 平台（Linux/macOS 需换 SDL2，不在本项目范围）。
- 不支持 DirectInput-only / 非 XInput 兼容设备。
- 不采集键盘、鼠标输入。
- 不记录震动反馈的输出（只读输入）。
- 不做实时视频录制/回放（可视化只展示实时状态，不保存画面）。

### 反目标（Anti-goals，即使技术上可行也刻意不做）
- 不做按键注入、宏、连发、作弊功能——保持"只读测量仪器"定位，这对学术可信度至关重要。
- 不做内核驱动 / 反作弊绕过——复杂度与法律风险过高。

## 3. 约束（Constraints）
- 平台：Windows 7+（`xinput1_4.dll` 系统自带）。
- Python 3.10+。
- 采样线程的调度抖动：Python 的 `time.sleep()` 在 Windows 上精度约 1 ms 且可能更差；要达到稳定 1 kHz 需在采样间隔末期自旋等待（busy-wait），会占用一个逻辑核的部分 CPU。设计上采用"先 sleep 大部分间隔，末段自旋"的自适应策略，并在自检工具中**实测并报告**达成率与抖动，不虚标精度。
- 数据体积：连续 1 kHz 记录会产生较大文件（CSV 约 60–100 MB/小时/手柄）。提供"变化时才记录"的可选模式以降低体积。

## 4. 方案（Approaches）

考虑过三条路，用户已选定路线 1：

| 方案 | 做法 | 取舍 | 结论 |
|---|---|---|---|
| 1. ctypes 直调 XInput ✔ | 后台线程高频轮询 `XInputGetState()` | 纯 Python、无改游戏、精度高、可打包成 pip 库；仅 Windows、有调度抖动 | **选定** |
| 2. pygame.joystick | 事件泵读取 | 代码最少；时间精度受事件频率限制，反应时研究不够理想 | 放弃 |
| 3. Interception / 内核钩子 | 驱动级捕获 | 精度最高、可抓键鼠；需内核驱动与签名，复杂度过高 | 放弃 |

## 5. 设计要点

### 5.1 采集的数据字段（每个采样点）
- `timestamp_us`：高精度单调时钟时间戳（`time.perf_counter_ns()` / 1000，单位微秒）
- `packet`：XInput `dwPacketNumber`（状态变更时递增，用于交叉校验）
- `buttons`：16 位按键位掩码（A/B/X/Y、LB/RB、Back/Start、L3/R3、DPad）
- `lt` / `rt`：左右扳机压力 0–255
- `ls_x` / `ls_y` / `rs_x` / `rs_y`：左右摇杆 -32768…32767
- `connected`：手柄连接状态

### 5.2 架构
- **采集线程**：独立后台线程循环轮询 `XInputGetState()`，把二进制状态写入线程安全队列（`queue.Queue` 或环形缓冲）。只读，不写设备。
- **写入线程 / 主线程**：从队列消费并落盘，避免 I/O 阻塞采样循环。
- **可视化推送**：同一份状态流另有一路订阅者，以 **30 Hz** 降采样后推送给 Web 仪表盘（推送频率可配置）。绘图与网络 I/O 绝不在采集线程内做，采集精度不受可视化影响。
- **自适应定时**：`sleep(interval * 0.6)` 后在剩余时间内自旋，平衡精度与 CPU 占用。
- **热插拔**：`ERROR_DEVICE_NOT_CONNECTED` 时保持轮询并在状态中标记 `connected=false`，手柄重新插入后自动恢复；断开期间照常写入带 `connected=false` 标记的时间戳行，重连后在同一会话内续录（设计方决定：不拆分为多个会话）。
- **多手柄**：`XInputGetState(0..3)`，最多 4 个。设计方决定：一个 `ControllerRecorder` 实例绑定一个 `user_index` 槽位；记录多个手柄需开多个实例、各写各的文件（简单、边界清晰）。

### 5.3 公共 API（草拟）
```python
from xinput_recorder import ControllerRecorder

with ControllerRecorder(hz=1000, user_index=0, dashboard=True) as rec:
    ...          # 游戏在这段代码运行期间照常游玩；仪表盘同步在浏览器打开
session = rec.session

session.to_csv("session.csv")          # pandas 友好
events = session.events()              # 按键按下/抬起事件 + 按压时长
force = session.trigger_curves()       # 扳机力度曲线
traj = session.stick_trajectory()      # 摇杆轨迹 + 抖动/震颤指标
```
CLI：
```bash
xinput-record --hz 1000 --out session.csv --user 0 --dashboard   # 边录边看
xinput-selftest          # 实测并报告采样达成率与抖动
```

### 5.4 输出格式
- 默认 CSV：表头 + 每采样一行，UTF-8，时间戳为整数微秒（便于精确对齐）。
- 可选 `change_only` 模式：仅在状态变化时记录（附带变化前状态持续时间），大幅减小文件。
- 加载函数 `load_csv()` 返回可交给 pandas 的 `Session` 对象。

### 5.5 衍生分析（分析模块）
- 按键事件：按下/抬起时间、按压时长、点击间隔
- 扳机：力度曲线、峰值力度、按压上升/下降时间
- 摇杆：轨迹、径向位移、抖动/震颤幅度（可服务于运动控制研究）
- 统计：采样达成率、丢采率、抖动分布

### 5.6 实时可视化（Web 仪表盘）
- 用户已选定形式：**Web 仪表盘**，便于副屏/手机/平板（同一 Wi-Fi 访问 `http://<本机IP>:<端口>`）观看。
- 技术栈（设计方决定，契合"核心零强制依赖"）：服务端用 Python 标准库 `http.server` + **SSE（Server-Sent Events）**单向推送；浏览器用原生 `EventSource` + Canvas 绘制。**不引入 WebSocket / Flask / 前端框架**。
- 推送频率默认 30 Hz（可配置），远低于 1 kHz 采集频率；录制精度与落盘不受影响。
- 仪表盘展示内容：手柄轮廓图（按键高亮）、左右摇杆位置散点、扳机压力条、实时采样率/丢采统计；附一个简短的按键/力度滚动曲线。
- 仪表盘随 `ControllerRecorder(dashboard=True)` / `--dashboard` 自动启动；CLI 打印访问地址与端口（端口可配置，默认 8765）。
- 安全：HTTP 服务默认只监听 `127.0.0.1`；需局域网访问时显式加 `--host 0.0.0.0`，并在文档中提示风险。

### 5.7 打包与分发
- `pyproject.toml`，核心仅依赖标准库（含 Web 仪表盘）；分析模块可选依赖 pandas。
- `pip install .` / 后续发布 PyPI。

## 7. 验证标准
- `xinput-selftest` 在目标机器上报告实际采样率接近配置值、抖动在可接受范围。
- 无手柄插入时记录器能稳定运行、正确标记断开、不崩溃。
- 录制的 CSV 可被 `pandas.read_csv` 读取，`events()` / `trigger_curves()` / `stick_trajectory()` 在无数据或边界输入下不报错。
- 在真实游戏运行时后台采集，游戏帧率无可见下降（只读机制保证）。
- 启用仪表盘后，浏览器能实时显示按键/摇杆/扳机状态；开启可视化时录制采样率与不开启时基本一致（可视化不影响采集精度）。
